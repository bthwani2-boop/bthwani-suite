# 11_FIRST_SCREEN_RULE

## First Screen

- selected screen: `dsh_client_entry_discovery_home`

## Why This Screen Opens First

- it exposes the lawful customer entry point for the whole service
- it reveals the first real UI-Kit needs without requiring service methods or contract expansion first
- it opens the next two client screens naturally: detail selection and cart review
- it stays below runtime-proof dependence because current target shell already supports fixtures-only route candidates

## What Must Exist Before It

- shared page shell
- category and store cards
- section header and search affordance primitives
- loading, empty, and retry state shells

## What It Prevents From Opening Early

- partner and captain work before customer entry is explicit
- contract expansion before the client information architecture is stable
- proxy governance before the mainline customer path is visible
