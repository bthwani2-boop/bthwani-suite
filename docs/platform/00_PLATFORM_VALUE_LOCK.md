## Core Platform Value

The current rebuild value of `bthwani-suite` is:

- one governed multi-surface platform
- one clean ownership model
- thin delivery surfaces over service truth
- high-frequency operational journeys that remain simple for each actor
- any platform financial effect routes through `WLT` only

## What The Platform Must Do Now

At the current rebuild stage, the platform must prove that it can support:

- a clean multi-surface operating model across approved surfaces
- one high-leverage service journey before broad expansion
- service-owned truth rather than app-owned truth
- mutable operational policy through `VAR_*` rather than hardcoded execution policy
- reusable UI Kit growth from real service needs
- contract change only after UX and service demand are known

## Core User Value Lock

The first meaningful value target is not “rebuild everything.”

The first meaningful value target is:

- pick one service with strong cross-surface reach
- define that service truth clearly
- use it to expose real screen, contract, and UI Kit needs
- keep all other services deferred until the first service path is governed

## Simplicity Lock

The platform must remain simple in these ways:

- one primary service in focus at a time
- one primary path per actor where possible
- no duplicate or side-money ownership outside `WLT`
- no donor structure carryover as a shortcut
- no early runtime, generated layers, or binding during bootstrap

## Fast-Path Lock

Where a task is high-frequency for its actor, the rebuild should prefer low-friction flow shape.

This means:

- direct entry to the actor’s main job
- reduced route clutter
- reduced unnecessary branching
- no competing primary CTAs for the same job

## Evidence Basis

This value lock is based on:

- Phase 02 target repo census and bootstrap shell state
- observed donor multi-surface set in `apps/mobile/` and `apps/web/`
- observed donor service set in `services/`
- current governing rules for `control-panel` and `WLT`
- donor repo README describing an integrated monorepo across web, mobile, services, contracts, and tools

## Explicit Value Exclusions At This Stage

- not a full platform rebuild in one wave
- not a runtime-first validation program
- not a donor parity program
- not a screen implementation phase
- not a generated-client phase
