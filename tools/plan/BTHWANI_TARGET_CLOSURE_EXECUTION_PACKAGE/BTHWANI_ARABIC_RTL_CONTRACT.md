# BTHWANI ARABIC RTL CONTRACT — V7

هذا الملف هو المرجع الموحد لجميع قواعد العربية والـ RTL عبر كل أسطح BThwani.

القواعد في هذا الملف **إلزامية** وتُطبَّق على:
- app-client
- app-partner
- app-captain
- app-field
- control-panel
- marketing surfaces
- ui-kit components

## 2. اتجاه المحتوى — القاعدة الصارمة

### 2.1 RTL — ما يخضع لـ RTL دائماً

```text
النص العربي
العناوين
الوصف
التسميات (labels)
أزرار الإجراءات
رأس الصفحة (header)
الشريط الجانبي (sidebar)
الملاحة (navigation)
أيقونة + نص: الكتلة على اليمين، الإجراء أو السهم على اليسار
محاذاة النص: يمين
```

### 2.2 LTR — ما يخضع لـ LTR دائماً

```text
رموز المنتج (SKU)
GTIN / barcode
أرقام هاتف دولية
URLs
كود مصدري
timestamps بصيغة ISO
IDs النظام
```

### 2.3 Mixed — ما يُعالج بحذر

```text
الأرقام: تتبع اتجاه المحتوى المحيط
السعر: عرض الرمز ثم الرقم بترتيب RTL صحيح (مثال: ٢٥٠ ر.س لا ر.س 250)
التواريخ: صيغة عربية يمين (يوم/شهر/سنة) مع exception للـ ISO timestamps
```

## 3. عناصر الـ UI — قواعد الاتجاه

### 3.1 أيقونة + نص (cluster)

```text
القاعدة: الكتلة (أيقونة + نص) على اليمين
السهم أو الإجراء (chevron, action button): على اليسار

مثال صحيح:   [أيقونة] اسم القسم          ‹
مثال خاطئ:   ›          اسم القسم [أيقونة]
```

### 3.2 المحاذاة في القوائم

```text
النص العربي: right-aligned
أرقام/dates/IDs: left-aligned (LTR exception) أو center حسب السياق
badge/status: يتبع اتجاه RTL المحيط
```

### 3.3 المسافات والـ padding

```text
safe spacing: استخدم paddingStart/paddingEnd بدل paddingLeft/paddingRight
safe margins: marginStart/marginEnd
لا overflow أو clipping على النص العربي بسبب fixed width
```

### 3.4 السهم chevron

```text
التنقل للأمام (navigate right/forward in LTR) = في RTL يعني ‹ (سهم يسار)
الرجوع (back) = في RTL يعني › (سهم يمين)
هذا المعنى معكوس تماماً عن LTR — لا تُطبّق LTR منطق مباشرة
```

## 4. نظام الألوان المركزي — قواعد الاستخدام

```text
لا hardcoded colors خارج @bthwani/ui-kit
لا random HSL أو HEX داخل screen أو topic
لا local color variables
كل لون يأتي من:
  @bthwani/ui-kit token system
  أو central color contract في ui-kit

أي لون جديد يحتاج:
  1. إثبات الحاجة بالدليل
  2. إضافة إلى ui-kit أولاً
  3. استخدامه من هناك
```

## 5. نصوص الواجهة بالعربية — معايير الجودة

### 5.1 الممنوع في نصوص UI

```text
ترجمة حرفية من الإنجليزية
نص AI-generated بدون مراجعة بشرية
نص مبهم أو عام (مثال: "اضغط هنا"، "المزيد")
نص مفرط الطول يكسر layout
نص يختلط فيه الإنجليزي والعربي بدون سبب
نص تقني خام (error codes, stack traces) في واجهة المستخدم
```

### 5.2 المطلوب في نصوص UI

```text
واضح ومختصر
يصف الإجراء لا الموقع (مثال: "عرض التفاصيل" لا "اضغط للتفاصيل")
يستخدم لغة تشغيلية مباشرة
يتسق عبر الأسطح (نفس المصطلح للشيء نفسه)
مراجعة بشرية لأي نص يظهر للمستخدم النهائي
```

### 5.3 حالات UI العربية الإلزامية

```text
كل شاشة تغطي:
  حالة التحميل: رسالة عربية لا spinner أعمى
  حالة الفراغ: إرشاد واضح لا مستطيل فارغ
  حالة الخطأ: رسالة قابلة للفهم + إجراء
  حالة المحظور: سبب واضح + جهة الاتصال
  حالة التعطيل: tooltip يشرح السبب
  حالة النجاح: تأكيد واضح
```

## 6. الاختبار والتحقق

### 6.1 قائمة فحص RTL إلزامية قبل أي UI visual gate

```text
[ ] النص العربي يُعرض من اليمين لليسار
[ ] الأيقونات تتبع RTL layout (لا mirror يدوي بدون سبب)
[ ] السهم chevron في الاتجاه الصحيح
[ ] لا clipping على النص العربي في أي breakpoint
[ ] padding/margin يستخدم Start/End لا Left/Right
[ ] الأرقام والـ IDs في اتجاه LTR الصحيح
[ ] الألوان مصدرها ui-kit لا hardcoded
[ ] لا visual drift بين الأسطح المختلفة لنفس المكوّن
```

### 6.2 أوامر التحقق

```powershell
# فحص اتجاه i18n
pnpm run guard:i18n-direction

# فحص استيراد Tamagui (يضمن عدم تجاوز ui-kit)
pnpm run guard:tamagui-import-boundary

# TypeScript للتأكد من صحة الكود
pnpm -w exec tsc --noEmit
```

## 7. قاعدة عدم الانجراف البصري

```text
VISUAL_DRIFT_FORBIDDEN:
  نفس المكوّن في app-client وapp-partner يجب أن يبدو متسقاً
  نفس العنصر في tabs مختلفة من control-panel يجب أن يبدو متسقاً
  RTL في مكوّن واحد لا يجوز أن يختلف عن RTL في مكوّن يستخدمه

أي divergence يُعدّ BUG وليس اختياراً تصميمياً.
```
